## Temuan berdasarkan prioritas

### P0 — Autentikasi dan isolasi pemilik belum diterapkan

`mcp-ts/src/server.ts:55` memakai header `x-owner-id` atau fallback `oauth-owner`; tidak ada validasi token OAuth, issuer, audience, expiry, atau scope. `GATEWAY_OWNER` pada baris 15–20 dapat menyatukan semua pengguna ke satu owner. `ownerFrom` tidak dipakai.

`gateway-go/internal/api/handler.go:25` mempercayai `X-Owner-Id` tanpa memverifikasi autentikasi request. `cmd/gateway/main.go` tidak memasang auth middleware. Token yang dikirim MCP ke gateway tidak diperiksa.

Probe lokal membuktikan:

| Request dengan data tiruan | Hasil aktual |
|---|---|
| `GET /internal/v1/devices` tanpa autentikasi | HTTP 200; fungsi store mengizinkan daftar seluruh owner bila owner kosong |
| Status perangkat milik owner lain | HTTP 200 |
| Baca task tanpa autentikasi | HTTP 200 |
| Cancel task milik owner lain | HTTP 200 |
| Buat task dengan header owner tiruan tanpa Authorization | Diterima dan didispatch |
| MCP `device_list` tanpa Authorization, gateway mock | HTTP 200, tidak `isError`, diteruskan sebagai `oauth-owner` |

Perbaikan: autentikasi setiap jalur privileged, derive owner dari identitas tervalidasi, autentikasi internal MCP → gateway, dan cek kepemilikan untuk setiap read/write/cancel/status. Hilangkan fallback identitas produksi. Tambahkan tes negatif tanpa token, token palsu/kedaluwarsa/scope salah, serta lintas owner.

### P0 — Gateway menerima agent tanpa kredensial dan hasil task tanpa binding perangkat

`gateway-go/internal/api/handler.go:191` masih memiliki placeholder validasi device token. Koneksi hanya memerlukan `device_id`. Koneksi baru menimpa route perangkat pada baris 199. Hasil pada baris 234 diterima berdasarkan task ID tanpa memeriksa apakah task ditugaskan kepada perangkat pada koneksi tersebut.

Probe lokal membuktikan handshake tanpa kredensial menghasilkan HTTP 101. Perangkat tiruan kedua berhasil mengirim hasil untuk task perangkat pertama sehingga status menjadi `succeeded`.

Perbaikan: device credential/proof yang tervalidasi, binding sesi ke perangkat dan task, perlindungan replay, kebijakan koneksi ganda, rotasi/revocation, dan penyimpanan kredensial Windows yang aman. `agent-rust/src/cap/identity.rs` sekarang hanya menyimpan device ID dalam teks dan mengabaikan kegagalan penyimpanan.

### P0 — Persetujuan lokal dan emergency pause belum berfungsi

MCP meminta `approve:true` untuk delete/kill, tetapi flag tersebut berasal dari tool input dan tidak membuktikan persetujuan pemilik Windows. `agent-rust/src/main.rs:96` dan `:111` meneruskan operasi langsung. `files.rs` memanggil `remove_dir_all`/`remove_file`; `process.rs` menjalankan `taskkill`. Tidak ada dialog consent walaupun dependency `rfd` tercantum.

`state.rs:set_paused` tidak pernah dipanggil; compiler memperingatkan fungsi tidak digunakan. Agent tidak mengecek pause sebelum mengeksekusi task. Terminal dapat melakukan operasi sensitif tanpa local policy atau dialog persetujuan.

Perbaikan: local permission policy yang default-deny, consent native terikat ke task dan parameter, preview operasi destruktif, izin root folder/data sensitif, serta pause lokal yang menolak dispatch dan membatasi pekerjaan aktif sesuai kebijakan.

### P1 — Idempotency belum mencegah eksekusi ganda

Store mengembalikan task lama saat key sama, tetapi `handler.go:125–132` tetap mengirim `task_assign` lagi. Agent menjalankan setiap frame tanpa journal atau deduplication. Probe lokal mengirim dua request dengan key identik: task ID sama, **dua frame assignment**.

Key store tidak dibatasi owner/device dan tidak mengecek konsistensi payload. MCP juga membuat key dari waktu/random sehingga retry tool invocation tidak memakai key stabil.

Perbaikan: kembalikan task lama tanpa dispatch ulang; scope key ke owner/device, bind key ke payload, dan implementasikan journal deduplication pada agent. Jangan replay efek samping setelah hasil tidak pasti.

### P1 — Cancel, deadline, recovery, dan persistence belum lengkap

- `Store` menyimpan tasks/devices/pairing dalam map RAM; tidak ada database, migration, backup, atau restore.
- `Cancel` hanya mengganti status. Gateway tidak mengirim cancel ke agent, dan agent tidak menangani frame `task_cancel`.
- Probe lokal membuktikan late result mengubah task yang dibatalkan menjadi `succeeded`.
- `Assign` Rust tidak membaca deadline/idempotency key. Tidak ada state `uncertain` yang dijalankan, journal acknowledgement yang disimpan, atau recovery setelah crash.
- Agent mencoba koneksi sekali dan keluar saat WebSocket putus; tidak ada reconnect/backoff.
- Task dibuat saat perangkat offline tanpa mekanisme drain queue saat reconnect. Channel dispatch kapasitas 16 dapat penuh; task tetap queued tanpa worker pemulihan.
- Agent memakai `tokio::spawn` tanpa batas concurrency. Store mengembalikan pointer mutable dan handler mengubah state di luar lock; tes bawaan tidak mencakup concurrent handler traffic.
- Goroutine writer koneksi tidak menutup channel ketika koneksi berakhir.

Perbaikan: storage durable sederhana, state machine yang valid, cancel end-to-end, absolute deadline, bounded concurrency/queue, reconnect/backoff, graceful shutdown, result acknowledgement, retention, dan explicit uncertain state.

### P1 — Desktop automation masih placeholder; screenshot belum dikirim sebagai gambar MCP

`agent-rust/src/cap/desktop.rs:66` mengembalikan `ok:false,deferred:true` untuk mouse, keyboard, focus, dan clipboard. Double click/right click/drag yang diterima schema MCP justru masuk `unknown interact action`. Karena nilai placeholder merupakan `Ok(...)`, wrapper agent dapat melaporkan task `succeeded` meski interaksi tidak terjadi.

Screenshot asli bisa dibuat melalui PowerShell, tetapi hanya memakai PrimaryScreen dan mengabaikan parameter monitor. MCP wrapper `server.ts:59` selalu menghasilkan content `text`; `task_status` tidak mengonversi base64 menjadi MCP image/resource. Tidak ada implementasi active-window detection, UI Automation, DPI/multi-monitor, atau pemeriksaan sesi desktop berizin/secure desktop. Launch mengabaikan `args` dari tool schema dan memakai `cmd /C start`.

Perbaikan: implementasikan native input/UI Automation dengan guard sesi desktop; kesalahan/fitur unsupported harus menghasilkan failure yang jelas. Kirim screenshot lewat MCP image/resource yang didukung dan uji render gambar di ChatGPT.

### P1 — Pengalaman install/pairing/tray dan update belum tersedia secara lengkap

Tidak ada tray/window native atau UI status koneksi, pairing, reconnect, permission settings, approval, disconnect, diagnostik, dan update. Default gateway agent adalah `ws://localhost:8080`; installer tidak memberikan konfigurasi gateway produksi atau alur pairing.

NSIS script tersedia, tetapi `installer/OpenCommanderSetup.exe` dan `agent-rust/target/release/OpenCommander.exe` tidak ditemukan saat audit. Installer meminta admin, menulis autorun tanpa quoting path, dan uninstall tidak menghentikan proses atau memeriksa kegagalan delete. Tidak ada upgrade orchestration, rollback, cleanup pairing/revocation, atau pipeline rilis Windows.

Tidak ditemukan implementasi version checking, signed metadata verification, download/checksum, upgrade, atau rollback update. Dokumentasi menyebut unsigned development release; sertifikat Authenticode bukan pengganti kebutuhan implementasi updater aman.

### P2 — Kemampuan file, terminal, dan sistem masih sebagian

- File: operasi dasar tersedia; belum ada batch, preview destruktif, kebijakan root, perlindungan junction/hardlink, atau overwrite policy menyeluruh. Nama temp write tetap dan tidak aman untuk concurrent writes. Copy/unzip dapat menimpa tanpa guard yang setara. File read/hash membaca seluruh file ke RAM sebelum pembatasan hasil. Search hanya nama, dibatasi jumlah entry yang ditelusuri, bukan pencarian konten seperti deskripsi MCP.
- Terminal: PowerShell/CMD, cwd, stdout/stderr, exit, dan timeout dasar ada. Belum ada environment input, streaming, task cancellation, durable output, atau Windows Job Object untuk cleanup seluruh process tree. Pembatasan output terjadi setelah seluruh output dikumpulkan.
- Sistem: OS/CPU/RAM/uptime dan process list tersedia; disk/network/services/installed apps/system diagnostics belum lengkap. Field `*_kb` memakai nilai memory sysinfo tanpa konversi eksplisit ke KB. Suspend/resume process ditolak karena membutuhkan PsSuspend yang tidak dibundel.
- MCP: 17 tool wajib ditemukan. Tidak satu pun punya `outputSchema` atau `securitySchemes`; tidak ada timeout fetch gateway. Deklarasi tool tidak membuktikan capability agent telah berfungsi.

### P1 — Acceptance ChatGPT biasa belum terbukti

`docs/ACCEPTANCE.md` secara eksplisit menyebut acceptance belum dijalankan. Tidak ditemukan bukti empat skenario di percakapan ChatGPT biasa dengan request ID/task ID yang cocok. Bukti curl atau endpoint health hanya membuktikan lapisan server/agent terkait, bukan acceptance host target.

Dokumentasi resmi mendukung custom MCP plugin dengan read/write tools, tetapi akun/workspace target dan keberhasilan linking tetap harus diuji. Klaim `TIDAK ADA HAMBATAN PLATFORM` dalam `VALIDATION_CHATGPT.md` terlalu kuat jika hanya berdasarkan dokumentasi tanpa acceptance akun tersebut.

Sumber resmi yang dibuka pada audit:

- [Add custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server).
- [Authentication](https://developers.openai.com/plugins/build/auth): validasi token dan deklarasi OAuth harus diterapkan; metadata saja tidak mengamankan invocation.

### P2 — Dokumentasi dan deployment menjanjikan fitur yang belum ada

`docs/SECURITY.md` menyebut native consent, tray pause, device credentials, persistent journal, dan safe update seolah sudah tersedia. Source saat ini tidak mengimplementasikan klaim tersebut. Protokol juga menjanjikan token, TTL pairing, nonce, cancel, pause, dan uncertain recovery yang belum ditegakkan.

Compose tidak memiliki persistent volume/database/OAuth service/TLS deployment configuration. Tidak ditemukan backup/restore/migration scripts atau CI workflow. Dockerfile MCP untuk Compose menginstal dependency produksi sebelum build TypeScript, sehingga compiler build bergantung pada fallback `npx`; perlu build stage yang eksplisit. Dockerfile root berbeda dan memang memiliki build stage TypeScript.

`mcp-ts/dist/server.js` dilacak Git walau `dist/` di-ignore, dan tidak identik dengan source saat dibuild: source memiliki `GATEWAY_OWNER` override yang tidak ada di artefak tracked. Perlu satu sumber build rilis yang konsisten.
